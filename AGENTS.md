# Порядок выполнения задач

Для каждой новой задачи обязательно соблюдай следующий процесс:

1. Разрешено провести только безопасное исследование: прочитать необходимые
   файлы, найти связанный код и проверить текущее состояние проекта.
2. Не изменяй файлы, не устанавливай зависимости и не запускай команды,
   изменяющие состояние проекта.
3. Сначала представь пользователю краткий, конкретный план действий.
4. Укажи, какие файлы предположительно потребуется изменить и как будет
   проверен результат.
5. Заверши ответ словами: «Жду подтверждения плана».
6. Не приступай к реализации, пока пользователь явно не подтвердит план
   словами вроде «утверждаю», «приступай» или «выполняй».
7. Если пользователь изменил требования, обнови план и снова запроси
   подтверждение.
8. После подтверждения выполни утверждённый план и проверь результат.

# Единый интерфейс игровых режимов

- Перед изменением игрового поля или добавлением режима обязательно прочитай [регламент малого круга](docs/rat-race-interface.md) и [DESIGN.md](apps/web/DESIGN.md).
- Интерфейс 101 — основа всех режимов малого круга. Используй общие компоненты поля, вкладок, карточек ходов, выпавших карточек `JournalCard`, строки броска и перемещения `TurnMovement`, форм и калькуляторов сделок, предложений, отчётов, плашек, прогресс-баров и панели «Ваш ход».
- Режим передаёт свои данные, расчёты, правила и доступные действия. Не создавай отдельную компоновку, копии общих компонентов или похожие формы со своими стилями без явного согласования с пользователем; соответствие требуется для содержимого и состояний, а не только внешнего контейнера.
- Соблюдай область действия правил: регламент малого круга не заменяет описание большого круга в `DESIGN.md`. Не переноси компоновку, вкладки или цветовую семантику между кругами без согласования.
- Проверь затронутые поверхности 101 и изменяемого режима на компьютере и телефоне по критериям регламента. В отчёте укажи фактически проверенные режимы, сценарии и размеры, результаты и ограничения; непроверенные пункты не выдавай за выполненные.

# Фишки в игре

- Фишка, выбранная перед началом партии, используется везде внутри этой партии: на обоих кругах, в карточке игрока, истории действий, отметках владения и игровом меню.
- Правило одинаково для людей и ботов; аватар профиля не заменяет выбранную фишку.

# Правила ботов

- После каждого изменения поведения ботов обновляй `docs/bot-rules.md`, чтобы описание уровней сложности соответствовало действующей логике игры.

# Правила работы с журналом изменений

- Каждая доработка, которая меняет поведение или интерфейс системы, должна добавлять краткую запись в `docs/changes.json`.
- Описание пишется для пользователя: одним предложением, без названий внутренних классов, функций и файлов.
- Новая запись добавляется в релиз `unreleased`. При подготовке релиза записи переносятся в блок с фактической версией и датой выпуска.
- Для записи используется одна из категорий: `feature`, `improvement`, `fix`, `technical`.
- Чистое форматирование, правки комментариев и другие изменения без влияния на систему отдельной записи не требуют.
- Доработка считается завершённой только после успешного выполнения `npm run changes:check`.
